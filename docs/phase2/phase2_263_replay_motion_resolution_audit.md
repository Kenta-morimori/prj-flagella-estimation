# Issue #263：2Dの見かけの停止と保存座標の切り分け

2026-11-12。Refs #263 / PR #264。#44の成果物取得がcs10のDNS接続障害で保留の間に、検証済みの既存#42 DJを用いて表示の性質を確認した。**低解像度の2D菌体描画には、重心が移動していても同じ画像になる区間がある。これを物理的な停止やモデル修正の根拠に使わない。** 物理source・実行条件・標準renderer・QC gateは変更していない。

## 検算した条件と方法

- 既存#42のDJ、simulation commit `59890c05460ba3032d50813afaa488ed3440f271`。3.5秒の完走・strict QC PASS済みarchiveを使った。portable37件の集合・件数・全SHAを再照合し、run_summaryを先に読んだ。
- 既存の定性replayと同じ176frame、物理0〜3.5秒、共通固定視野を再現した。JのFAIL archiveは歴史的な共通視野範囲の再現にだけ用い、物理的な採択・比較には使わない。
- 元replayのrender commit `6df19fa2c6e9868ed7157ade0a35370f34ad7135` と解析source `e32c4ad033411c4bbdfb3fcc6583eab10b93e08e` で、`body2d.py` と `phase2_replay.py` に差がないことを確認した。
- 2Dの1条件あたりの描画領域は256×256画素、視野幅7.03019 µm、1画素は0.0274617 µm。追従cameraは使わない。
- 保存座標、同じ姿勢からの標準描画、同じ視野で各軸の画素数だけを4倍にした描画を比較した。時刻・姿勢・物理座標は共通である。

## 確認できた事実

| 項目 | 結果 |
| --- | --- |
| 隣接frameの物理時間間隔 | 約0.02秒 |
| 保存されたXY重心が移動した区間 | 175/175 |
| 1区間のXY重心移動量 | 最小.000297、中央値.004229、最大.014870 µm |
| 標準256画素で同じ菌体描画になった区間 | 78/175（44.6%） |
| 同じ描画が続いた最長の物理時間 | .12秒 |
| 1024画素・同一視野で同じ描画になった区間 | 12/175（6.9%） |
| archiveの重心とbody bead平均座標との差 | 最大2.43e-16 µm |

保存された重心位置が一定間隔でしか更新されていない、という不具合はこのreferenceでは見つからなかった。移動量の中央値は標準画素の約0.154個分であるため、1frameごとの変化が整数画素の境界を越えないことが多い。

既存の[菌体描画処理](https://github.com/Kenta-morimori/prj-flagella-estimation/blob/e32c4ad033411c4bbdfb3fcc6583eab10b93e08e/src/sim_swim/render/body2d.py#L163-L185)では、カプセル中心線の両端を整数画素へ丸めてから線を描く。両端の丸め値が変わらなければ、保存重心が少し移動していても同じ菌体画像となる。一定姿勢で.01 µmだけ並進する合成例でも、粗い描画は同一、同じ視野の4倍解像度では変化することを確認した。

## この検算で断定しないこと

ここで数えた同一画像は**符号化前の菌体カプセル**であり、文字・目盛り・非可逆MP4圧縮を含む動画全体のbit一致ではない。#42 DJの表示に対する検算であり、#44の実行/QCや物理的な改善の証拠ではない。

XY重心の移動は、菌体の前方へ進むことと同じではない。前進方向の速度が低下・反転しているかは、保存座標から菌体軸方向の符号付き速度と周期ごとの平均を計算して判定する。既存DJの速度変動や束未達が、画素化だけで説明できたとは主張しない。

2Dは一様なカプセルの投影であり、長軸まわりの材料点自転を直接観察する表示ではない。自転はlabel付きbody座標の回転と3Dで確認し、online PCA-frame rollやシルエットの静止と同一視しない。

## #44の評価へ反映すること

1. 標準の共通strict QC・固定camera replayは従来条件を維持する。
2. 物理的な前進・停止・後退は、保存された重心座標と菌体軸から定量する。
3. 補助の定性2D replayは、同じ固定視野で高解像度にする。表示用の変更をsimulation条件や標準rendererの採択へ混ぜず、render-only overrideと画素サイズ・frame/fps/coverage/SHAを記録する。
4. 高解像度化でも表示サイズや動画圧縮による限界は残るため、動画だけで滑らかな遊泳を採択しない。
